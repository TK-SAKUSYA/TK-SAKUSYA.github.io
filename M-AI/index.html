EXPERIMENTAL · VERSION 0.22.0

M-AI

観察と経験から学び、それぞれの名前と性格を持って活動するMinecraft AIプレイヤーシステム。

第二十一回アップデート

  • 新しいファイル名のビルドworkflow「m-ai-fresh-build.yml」を追加
  • 以前のworkflow登録に依存せず、GitHub Actionsへ新規workflowとして登録し直す対策
  • M-AIのソース・ビルド関連ファイルの更新時に実行し、手動実行にも対応
  • ビルドとZIP作成の処理は既存workflowと同じ内容を維持
  • 新workflowが正常起動するかは、実行結果を確認するまで未確定
  • プロジェクトを0.22.0へ更新。Mod本体は0.7.0のまま
  • JAR・試遊ZIPはまだ生成確認できていない

第二十回アップデート

  • GitHub Actionsの実行記録を調査
  • 失敗 run が通常のビルド workflow ではなく、GitHub側の合成された BuildFailed workflow に紐づいていることを確認
  • ジョブ数は0。Node.js・Java・Gradleの処理開始前に停止
  • 再実行もGitHub APIから拒否された
  • GitHub Communityに同じ BuildFailed / startup_failure / 0 jobs の報告があることを確認
  • GradleやMinecraftのソースを根拠なく変更せず、GitHub側のworkflow登録・イベント振り分け問題として切り分け
  • プロジェクトを0.21.0へ更新。Mod本体は0.7.0のまま
  • JARと試遊ZIPはまだ未生成

第十九回アップデート

  • GitHub Actionsの実行環境をUbuntu 24.04に固定
  • Node.js・npm・Java・Gradleのバージョンをビルド前に記録する診断ステップを追加
  • 起動前の失敗と、Gradleコンパイル失敗を切り分けやすくする
  • Fabric Modを0.7.0へ更新

第十八回アップデート

  • ビルド成功時の配布物に M-AI-Chat-Playtest.zip を追加
  • JAR・Windows起動ファイル・設定例・通信ブリッジを1つのZIPにまとめる
  • 導入手順を「JAR配置→起動ファイル→Minecraftで会話」に整理
  • Fabric Modを0.6.0へ更新
  • ZIPはGitHub Actionsのビルド成功後にのみ生成

第十七回アップデート

  • Windows用 start-bridge.bat を追加、2つのローカル処理をまとめて起動
  • プレイヤーが新しいチャットを送ったときだけAIが返答
  • 起動前の古いチャットを誤って再生しない
  • Minecraft 26.3公式サンプルに合わせてGradle依存関係を修正
  • Fabric Modを0.5.0へ更新
  • 今回は会話だけの試作版。移動・採掘・建築・AIプレイヤー生成は未対応

第十六回アップデート

  • Minecraftの通常チャットでプレイヤーがAIに話しかけられる
  • プレイヤーの発言をローカル通信ブリッジへ転送・保存
  • 最新のワールド観察情報と一緒にローカルOllamaへ送信
  • AIの返事をMinecraft内のチャットへ [M-AI] として表示
  • 通常のMinecraftチャット送信は妨げない
  • Fabric Modを0.4.0へ更新
  • 移動・採掘・建築・AIプレイヤー生成はまだ未実装

第十五回アップデート

  • Minecraft内のチャット欄に [M-AI] としてAIの発言を表示
  • 通信はこのPC内の127.0.0.1限定
  • Fabric Modを0.3.0へ更新
  • 会話の入力や移動などのゲーム操作はまだ未実装

  • 現在いるディメンションを送信

  • ゲーム操作やAIプレイヤー生成はまだ未実装

第十三回アップデート

  • AIの考察をMinecraftの操作にはまだ接続していない

  • 127.0.0.1限定のTCP通信・JSON Lines形式・接続確認を実装

  • この段階ではMinecraftの操作やAI判断はまだ未接続

第八回アップデート

  • 小さな壁（横3×高さ2）または柱（高さ3）を建築
  • 必要なブロック数・設置先の空き・足場を確認

第七回アップデート

  • 操作担当者の明示的な指示でブロックを1個設置
  • 所持アイテム・設置先の空き・隣接する足場を確認
  • 保護対象ブロックや液体などへの設置を回避

第六回アップデート

  • 操作担当者の明示的な指示でアイテムをクラフト
  • 所持素材とレシピを確認してから実行
  • 近くに作業台があれば利用
  • 1回の指示につき最大4回分に制限

第五回アップデート

  • 操作担当者の明示的な指示で1ブロックを採掘
  • 採掘範囲・到達可能性・ブロック状態を確認
  • 採掘中の操作担当者による中断に対応

第四回アップデート

  • 操作担当者を全AIで共通化
  • 最初に !mai claim を実行したプレイヤーが全AIの操作担当者になる
  • AIごとに登録し直さず、全AIへの一括指示・停止・再開・記憶リセットが可能
  • 移動中も約150ミリ秒ごとに足場と障害物を確認
  • 進行方向に壁がある場合は移動を中断
  • 次の足場がない場合は移動を中断
  • 安全確認の情報が不足している場合も移動を中断
  • 人間の操作担当者による中断機能を維持
  • AI自身が決めた名前・自己紹介・性格・個別記憶を維持

重要な制限

第二十回ではGitHub Actionsの失敗記録を調査し、BuildFailedというGitHub側の合成workflowに割り当てられ、ジョブが0件のまま起動前に停止していることを確認しました。GitHub Communityにも同じ症状の報告があります。GitHub側のworkflow登録・イベント振り分けが正常に戻るまで、JARは生成できません。

今回の移動確認は簡易的な足場・障害物チェックです。完全な経路探索や、あらゆる危険の回避を保証するものではありません。

日記を書くAIには、あらかじめ本と羽ペンをインベントリに入れておく必要があります。言語モデルの事前学習知識そのものを消去することはできません。
